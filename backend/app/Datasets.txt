Search dataset records
Returns a paginated list of records with optional filters on dataset column names, optional modifiedAt range filters in the request body (use field modifiedAt with operators gt, gte, lt, lte and ISO-8601 instant values), and optional field selection. Regular column filters support operators eq and contains. Pagination and ordering use the same query parameters as GET /{datasetId}/records.

Filter index cap: The server may create at most one filter index per distinct filtered dataset column. The total number of filter-indexed columns per dataset is limited by your license (default 10; your server may use a different cap). If a search would exceed that limit, the request fails with HTTP 400 and the error message lists columns that are already indexed—reuse those columns or contact support to raise the cap.

List form submissions (multipart, encrypted)
Use multipart/form-data when the form stores encrypted submission payloads (or whenever you must supply the key as a file). Multipart part names:

private_key — RSA private key in PEM format (file upload). Used to decrypt submission XML and corrections; max 50KB. For encrypted forms you should include this part so field data can be decrypted (without it, responses may only expose non-secret metadata around the encryption manifest).
search — optional text part whose value is a JSON string (double-encoded: the part body is literal characters like {"filters":...}), with the same filters / fields JSON object shape as POST /submissions/search.
Query parameters (not multipart parts): cursor, limit, orderBy, orderByDirection — same as GET/POST search.

Non-encrypted forms: prefer GET /submissions or POST /submissions/search with Content-Type: application/json.

Returns cursor-paginated submissions using a JSON request body. filters may reference metadata fields only: submissionId, reviewStatus, formDefinitionVersion, submissionDate, completionDate. Supported operators: eq, contains, gt, gte, lt, lte, in (for in, provide a comma-separated list in value; at most 100 values). fields selects which keys to return and may include any metadata or form data field from the form definition.

For encrypted forms, upload the RSA private key and send filters as multipart instead: POST /api/v2/forms/{formId}/submissions with parts private_key (PEM file) and optional search (JSON string, same shape as this endpoint's body).
